# Observatory v0.1 telemetry inventory

Audited: 2026-10-02. Source: freshly fetched RoundWatch `origin/main`, matching local `main` at `6112aa983d1a139851d357055175149f16945495` (`Record Capacity Phase 0 baseline (#104)`).

This is a source inspection, not a measurement of the running Render instance. No production API, provider, payment, database, or worker was invoked. No application code, endpoint, configuration, or UI was changed. The only working-tree addition is this inventory. Production environment overrides, enabled instrumentation, deployed revision, and actual metric values were not verified.

The repository has no server-telemetry Observatory v0.1 field specification. The candidates below are the concrete fields and plausible aggregate signals in the requested categories. `apps/observatory` currently implements an offline Bazaar snapshot importer; it has no server telemetry collector or runtime DTO. That package's parser/report versions are unrelated to a server telemetry schema.

Main finding: worker health and dispatcher snapshots are already cheap memory reads. Durable capacity aggregates exist but are computed on each call. Resources exist only through an optional sampler that performs work and changes its CPU baselines. Traffic and operational events mostly exist as emitted logs, without an in-process aggregate. There is no existing complete, cached, side-effect-free service snapshot.

## A. Source-of-Truth Matrix

### Reading the matrix

Every row specifies existence/access, exact source field, update behavior, aggregation, complexity, acquisition effects, restart behavior, time basis, and DTO suitability. Fields grouped in a row have the same acquisition and lifetime; differences in meaning are stated explicitly.

Source labels resolve to the exact files/methods in the source map below. Line numbers refer to the audited commit.

- **Yes**: a current production-wired value/getter exists. **Optional**: requires `ROUNDWATCH_ECONOMICS_METRICS=1`. **Private**: state exists but lacks a public observation getter. **Log**: an event is emitted, without a retained queryable metric. **Missing**: the proposed aggregate is absent.
- **M** effects: memory/clock reads and allocating a returned object only; no SQLite, Indexer, other provider call, reconciliation, logging, or state mutation.
- **DB-R**: synchronous SQLite reads. **DB-P**: SQLite write/rollback readiness probe and readiness-cache mutation. **FS**: filesystem metadata/system calls. **NET-I**: Indexer requests through the shared dispatcher, necessarily provider calls too. **MUT**: additional in-memory mutation. **LOG**: emitted log.
- All unlisted effect types in a row are **No**. In particular, ordinary snapshots do not call the facilitator or run reconciliation. Reading logs requires a separate log source; no such collector exists here.
- **R**: resets with a new process/object. **D**: derived from durable database state; survives restart with the same database, subject to deliberate retention/restore. **CFG**: resolved at startup, reconstructed on restart; may change with deployment/environment overrides. **L**: log retention is external; the application does not retain the event.
- **I**: instantaneous/current observation. **C**: cumulative over the stated lifetime. **W**: latest cycle or interval, not an arbitrary rolling window. **T**: timestamp of the latest event.
- “O(1)” means bounded relative to number of watches/requests, not “free of I/O.” Constant-size SQLite probes still do work. Fixed six-purpose/category records count as bounded; cloning HTTP-status maps costs O(number of observed status codes).

### Watches, durable obligations, capacity, scan lag

Let **N** be retained watch rows and **A** be active rows. STORE `capacitySnapshot(currentIndexerRound?)` executes an unfiltered aggregate SELECT over all N rows, then an active-row SELECT. It is **not cached**. Producing the whole snapshot costs O(N + A log A), including sorting lag samples; memory is O(A). Counts alone still require SQL work. The timer's 60 s default sampling does not make these on-demand methods O(1).

All capacity rows below are Yes and exported in `RoundWatchCapacitySnapshot`. Normal acquisition effects are DB-R and M only: no Indexer/provider request, reconciliation, write, or logging. The caller supplies the cached tip; the store does not fetch one.

#### Exact Indexer purpose meanings

All six below exist as DISP `requests[purpose]` started-attempt totals (M/O(1) fixed key lookup, aggregated, R/C). Reading counters never causes requests. Invoking the cited operations **does** cause NET-I, dispatcher mutation and completion logging; no need to invoke them for Observatory.

| Exact purpose | Source/call sites and meaning | Attribution limits / DTO semantics |
|---|---|---|
| `activation` | APP after-settle calls IDX `lookupAssetTransfer(..., 'activation', watchId)` to obtain exact service transfer evidence | Includes post-settlement activation lookup, not facilitator settlement calls |
| `reconciliation` | REC exact service-tx lookup and current-round checks; IDX capability probe synthetic lookup uses this purpose too | Mixed recovery work and functional readiness probe; not recovered-watch count |
| `absence-proof` | IDX `searchTransactionPage` txid search pages; called by REC and capability probe | Mixed historical absence work and synthetic probe; HTTP success is not terminal absence proof |

There is no `foreground/background`, `probe/customer`, per-route provider outcome, retry-number, or payer dimension on dispatcher totals. Readiness traffic cannot be cleanly subtracted using just the purpose counters. A successfully allowed exact-lookup 404 remains a dispatcher success. Request operations include parsing/validation, so malformed HTTP 200 responses can be failures.

Optional per-watch Indexer `responseBytes` also has mixed acquisition semantics: successful consumed bodies use their bounded buffer length; allowed 404 uses declared Content-Length despite cancelling the body; non-OK responses use declared length when positive, otherwise bounded captured diagnostic bytes. A failure before the successful bounded-read assignment can retain zero. Treat it as instrumented response-size accounting, not actual transport bandwidth or a complete bytes-downloaded counter.

| Poll residual turns | attempted − succeeded − failed = no-op + evidence-only. Cannot derive isolated failures or separate residual categories |
| Remaining work | max(0, immutable per-watch budget − durable workUnitsUsed); unknown budget stays unknown. Fleet distribution requires DB aggregation; configured new-watch budget is not necessarily every historic budget |
| Backoff queue counts/age | New SQL aggregate using current state, terminal flag, expected txid/proof requirements, and retry timestamps. Keep due, deferred, and unserviceable separate |
| Retained all-state counts | New SQL GROUP BY state (+ terminal flag/reason when required). Persisted rows provide membership, not event dates/lifetime totals |
| Traffic classification/MCP transport counts | Offline or separate collector grouping structured HTTP logs. Explicitly excludes suppressed health/readiness and lacks tool names/JSON-RPC outcomes |
| Fingerprint cardinality | Distinct log fingerprints within one key epoch/window; not verified users/payers. Sampling/log loss/NAT/spoofing/collisions constrain interpretation; omit minimal DTO |

Not valid calculations with current data: rounds-to-seconds ETA without contemporaneous chain timing assumptions; p95 HTTP/provider latency from timing sums/max; cache hit ratio from terminal-pruned watch entries divided by lifetime dispatcher starts; lifetime matches from retained matched rows; revenue from HTTP `settled` labels; incident count from repeated readiness-blocked log lines; client demand from all HTTP traffic including bots/probes.

## D. Fields that should NOT be exposed

Exclude from an aggregate Observatory DTO, regardless of whether some are available through existing public watch APIs:

- Mnemonics, private keys, secrets, environment dumps, HMAC keys, signed payment payloads/headers, raw request/response/error bodies. Inspecting or collecting them is unnecessary for these metrics.
- Watch IDs, idempotency keys, addresses/payers/receivers, invoice notes/amounts, service/invoice/refund txids, watch-fingerprint/client-fingerprint values, raw proxy/client IP/UA, and per-watch purchase/evidence/checkpoint/retry records. Keep aggregation boundaries; pseudonymous fingerprints still allow correlation.
- Full provider URLs, raw database/host paths, provider correlation IDs/attempt IDs, internal stack traces/freeform error messages, promises/queues/cache query keys/continuation tokens and encoded pages. Allowlisted host/error-code/count diagnostics are sufficient.
- `finishWatch()`, `runOnce()`, `reconcileOnce()`, `runIfDue()`, paid-readiness check, gate `snapshot()`, or sampler `sample()` as Observatory read primitives. They respectively delete instrumentation, execute work, invoke probes, refresh admission evidence, refill tokens, or advance sampling baselines and perform I/O.
- Misleading aliases: activeWatchMetrics→active watches; progress heartbeat→chain coverage; poll succeeded→matched; dispatcher queue→watch backlog; generation→restart count; reconciliationAttempts→total attempts; worker providerHealth→facilitator health; cached currentIndexerRound→fresh chain head; WAL size→uncheckpointed work; HTTP success→unique service payments/revenue.
- Unavailable fields represented as zero/healthy, benchmark capacities/peak resources represented as live production metrics, configured caps represented as throughput/SLA, monotonic probe times represented as epoch dates.
- Unbounded raw logs, high-cardinality fingerprint/ID labels, per-watch metrics maps, SQL row arrays, provider error detail objects. A bounded snapshot should expose selected aggregates only.

This exclusion list is about the Observatory DTO's scope and stable semantics, not a change to the implemented public watch API.

## E. Recommendation for the minimal snapshot DTO

Use existing memory observation getters for the initial core. Do not make Observatory itself a readiness/probe/polling/reconciliation driver. Distinguish worker observation readiness from the existing complete public `/ready` result and stricter paid-admission decision.

Recommended minimal field contract (names below are **proposed**, not existing code):

| DTO field | Current source / acquisition | Include now? |
|---|---|---|
| `schemaVersion: 'observatory-runtime-v0.1'` | New fixed serialization label | Yes, proposed metadata |
| `observedAt` | Wall clock when building DTO | Yes; does not pretend every section was sampled then |
| `runtime.network`, `runtime.assetId` | Resolved NET/BOOT config | Yes |
| `runtime.economicsMetricsEnabled` | BOOT boolean | Yes; distinguishes unavailable optional data |
| `runtime.processEpoch` | New boot UUID/timestamp metadata, absent currently | Null until deliberately wired; required before reliable counter-delta charts |
| `runtime.deployedCommit` | Verified build/deploy metadata, absent currently | Null/omit; never substitute audited checkout SHA |
| `workers.poller`, `workers.reconciler` | Existing `healthSnapshot()` | Yes: `started`, `running`, `ready`, `cycleNotStalled`, `providerHealth`, `consecutiveFailures`, optional `lastCycleStartedAtMs`, `lastProgressAtMs`, `lastProviderEvidenceAtMs`, `lastErrorAtMs`. Document composite streak and heartbeat semantics; generation optional |
| `indexer.dispatcher` | Existing DISP `snapshot()` | Yes: `queued`, `inFlight`, fixed-key `requests`, `successes`, `failures`, `timeouts`; counters labeled since process/dispatcher creation |
| `indexer.observedRound`, `indexer.observedRoundAt` | POL capacity memory snapshot's cached tip/time | Yes nullable; label poller observation and preserve freshness |
| `pollCycle` | POL memory capacity snapshot | Yes nullable until `lastCycleDurationMs` exists: map exact source counts to `attempted`, `progressed`, `failed`, plus `durationMs`. State that residual turns exist and duration excludes post-cycle probes |
| `readiness` | No retained complete result/time | Null until a passive result from the existing readiness path is retained. Then `{ observedAt, ready, checks }`, without issuing a new check per Observatory read |
| `capacity` | Existing STORE/POL derived snapshot, currently produced by optional sampler but not retained | Null in strict memory-only core. Add only from a deliberately retained scheduled sample: `{ sampledAt, ...existing capacity fields }` |
| `resources` | Existing optional sampler, not retained | Null in strict memory-only core. Add from same retained sample: timestamps/elapsed, memory bytes, interval CPU microseconds, nullable sqlite/wal bytes |

A conceptual nullable shape:

```text
ObservatoryRuntimeV01
  schemaVersion, observedAt
  runtime { network, assetId, economicsMetricsEnabled,
            processEpoch: null|string, deployedCommit: null|string }
  workers { poller: WorkerObservation, reconciler: WorkerObservation }
  indexer { dispatcher: ProcessCountersAndGauges,
            observedRound: null|number, observedRoundAt: null|string }
  pollCycle: null|{ durationMs, attempted, progressed, failed }
  readiness: null|{ observedAt, ready, checks }
  capacity: null|{ sampledAt, existingCapacityAggregateFields }
  resources: null|{ sampledAt, elapsedMs, memoryBytes,
                   intervalCpuMicros, sqliteBytes, walBytes }
```

The core is bounded memory/config reads with no SQLite, file stat, provider traffic, work execution, logging, token refill, or CPU-baseline advancement. A DTO still needs serialization/wiring; **no endpoint currently returns this shape**.

To include capacity/resources without reader-triggered work, the smallest later change would retain the sample already produced on the sampler's cadence and serialize that retained object. That cache does not exist now. Storage/disk readiness would similarly need a retained observation from the normal readiness path; their completeness/freshness should remain distinct from worker-only health. This is a recommendation, not implementation authorization. Economics disabled, before-first-sample, stale sample, and collection failure need distinguishable availability/freshness, rather than default zeros. Record section timestamps and preserve old sample timestamps on failure.

Keep per-watch economics, free-work totals, raw HTTP events/fingerprints, MCP activity, operational logs, provider scoring, histories, revenue, and derived rates outside this minimum. The existing selected free-work totals could be an explicitly scoped later section, but cannot satisfy a complete HTTP/external traffic panel.

Counter policy: normalize the known six-purpose keys, preserve raw totals, declare process lifetime, and make downstream delta/rate calculations reset-aware. Do not subtract timeouts again from failures. Do not assume request starts equal completed outcomes+inFlight at every synchronous observation because completion/finally bookkeeping has a brief ordering boundary.

Capacity policy: use the existing unfinished-obligation predicate, preserve nullable tip/lag and sample count, retain closing-round clipping, and expose no watch rows/identifiers. A historical cached tip is not refreshed to make a snapshot appear complete. Latest-cycle fields are diagnostic observations, not a time series or latency SLA.
